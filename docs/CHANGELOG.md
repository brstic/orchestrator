# Changelog

Newest first. One line per change that someone using or developing the office would notice.

## 2026-11-11
- **A change of level, Claude account or model starts the session again by itself.** Saving a new autonomy level (to Unrestricted, or back to Auto), another Claude account, or another model or effort in an employee's profile used to wait for somebody to stop and start their session; meanwhile they went on "on the old one". Now the office starts the session again with the same conversation — at once if they are between turns, otherwise when their turn ends — and tells them to go on with their task. The one-time move to Unrestricted does the same for every session that was running. When several sessions of one Claude account stand at Claude Code's bypass warning together, your one "Yes, I accept" answers all of them.
- **Unrestricted: employees run without Claude Code's permission checks, and that is now the default.** A new level above Auto — Claude Code's bypass-permissions mode. Nothing an employee runs is checked or asked about by Claude Code, so nothing is refused by its safety check any more. The owner's decision, after the risks were put to them: it protects against nothing, including an instruction hidden in a page or a ticket an employee reads. Still in front of every command: the office's high-risk list (push, sudo, deploy, broad deletions, key files…), held until you answer and refused if you do not, and the project's deny rules. Everybody who was on Auto on the office's own machines was moved to it once; new hires by an owner start on it; put anybody back on Auto in their profile and they stay there. The first start on each Claude account asks you once to accept Claude Code's own warning. Owners only; a member's own computer is theirs to decide.
- **Deployed as build `ac3b086`** (15:18 UTC, from the collaborator's Windows computer): a server's folders picked from a list, and *Folders…* that no longer waits for ever. The desktop app has to be started again for the list. See `docs/STATUS.md`.
- **A server's folders are picked from a list: Browse the server…** My room → My servers → *Folders…* has a new button beside *Change the folders*. It shows the folders on the server as its own user sees them — starting in the home folder, with ↑, *Home*, a click to go into a folder, and **Add** / **Add this folder** to put one on the list — so nothing has to be typed from memory, and a folder outside the home folder (`/srv/…`) is found by walking to it. The app asks once per server in a dialog of its own before it reads the names (they are shown in the office's page). Looking changes nothing: the office may still work only in the folders on the list once *Change the folders* is pressed. Needs a desktop app started from this build, and the server deployed (the button is in the page).
- **Fixed: *Folders…* stayed on “Changing…” for ever, with no error.** It happened when the office's page was newer than the running desktop app: the page asked the app for something it could not do yet, the app refused, and nobody told the person. Every request from *My servers* to the app now comes back with an answer: *The Orchestrator app on this computer was started before this was added to it. Close the app, start it again, and try once more.* (`apps/desktop/src/lib/native-call.ts`; test `apps/desktop/test/server-folders.test.ts`.) Also: when the agent on a server is started again (*Folders…*, *Reconnect*), the app waits until the old one is really gone instead of one second.
- **What Claude Code refuses by itself, you can allow once.** An employee on Auto is sometimes refused an action by Claude Code's own safety check (an `ssh` to a server, a copy from one). Until now that was an alert and a dead end: your "yes" given through the office changed nothing, and employees wrote lessons about working around it. Now such a refusal arrives in the inbox as a request — the exact command, and the reason Claude Code gave — and **Allow** lets exactly that call through once (within ten minutes) and tells the employee, as a message from you, to run it again; **Deny** tells them to find another way. If Claude Code refuses it even so, you are told that plainly. Not yet tried with real Claude Code.
- **Work finds the right person in an office where everyone has the same trade.** A task that names nobody now goes to the colleague it is *about* — the one whose name, speciality or folder its title speaks of ("Marketplace: …" → whoever keeps the marketplace) — instead of to whoever is first in the list. Employees can propose tasks *for* a named colleague (`propose_tasks` → `assignee`), also for one on another project of the office, and hand a task over to one: that colleague is lent to the project and keeps their own. `get_team` now says what each colleague keeps (project, folder) and to whom work cannot be given.
- **Where nobody is a reviewer by trade, a colleague reviews.** A task that needs a review used to wait for you whenever the team had no reviewer, architect, security or QA role — in an office of full-stack engineers, always. Now a colleague on the project who does that kind of work gets the review (never the author); with *Employees manage the task board themselves* switched off it waits for you as before.
- Finished work that was already waiting for a review nobody had been asked for is given to a colleague when the office starts. Employees are told what to do when Claude Code refuses them (wait for the boss's word, do not work around it or pass it to a colleague) and to look in the vault and the memory before reporting that they lack access.
- Employees are told to write to each other briefly (the median message between two of them was over 900 characters, each one a turn of the reader's), and somebody who unblocks their own task no longer gets a message about it from themselves.

Only what is loud enough to be speech is sent; silence and the room's noise are not (a slider sets how loud, with a live bar of your microphone beside the mark). **V then switches the microphone off and on**, and a light at the bottom of the window is there the whole time: *Microphone on*, *Talking*, or *Microphone off*. - **The office is entered from a computer; a phone is told so.** Opening the office, or an invitation link, on a phone now shows a page: *the office opens on a computer* — a desktop or laptop, in a browser or in the app — and that an invitation opened there has not been used up. A phone gets nothing else either (not the API, not the door, not the live link). Tablets and computers are unaffected.
- **Other people in the office move smoothly.** Somebody else's character used to lurch and its legs stumble whenever they walked: at every report of their place (ten a second) the character was put where they were *now* and then pulled back to where it had got to, and its legs walked by that jolting. Now each character is drawn a third of a second in the past and moves evenly from one reported place to the next, by the sender's own clock, with the same real gait as your own character; a report no longer redraws anybody. Looking around on the spot is no longer shown as walking in place. Measured in a development office with a scripted second person walking at 3.8 m/s: drawn between 3.4 and 4.2 m/s with no step backwards (before: 1.4 to 11 m/s, with steps backwards). Smoothest once the other person's window has reloaded too (an older window sends no clock).
- **Step into a task somebody is working on.** A task in progress has a new card, *Step in*: write what should be different and **Send correction** — the employee is told at once (their turn interrupted in the terminal, unless you untick *interrupt now*) and goes on with the task; *Change the task's text…* edits its title, description and acceptance criteria in the same move. **Stop — put on hold** interrupts them, tells them to leave it and parks the task in the backlog with its branch until you release it again; **Stop and delete…** removes it. What they had half-done in their own worktree is committed on the task's branch as work in progress, so nothing is lost and their next task can start. Until now the only way was *Move to…*, which changed the board and told the employee nothing.
- **An employee waiting at a permission prompt in the terminal is no longer invisible.** When a request for approval was not answered in time, or the office was restarted while it waited (every deploy), Claude Code shows its own prompt in the terminal — and the office used to forget about it: no request in the inbox, the employee shown as "unknown", standing there for as long as nobody opened that terminal (one stood for fifty minutes on a `git push`). The office now sees the prompt on the session's screen, shows the employee as *needs approval*, asks again in the inbox, and gives your answer there with the prompt's own keys — the plain *Yes* or *No*, never "don't ask again". Answered at the terminal instead, the request goes away by itself.
- **A conversation that cannot be continued is no longer tried again and again.** A session stopped before its first prompt leaves no conversation behind; every later start failed with "No conversation found" and was repeated at each Start and each message (eight times in a minute, on a member's computer). The office now recognises that refusal and begins a new conversation at the next start.
- **A restart of the office waits for the old one to finish.** The launcher left 0.8 s after asking the server to stop, whether or not it had; started again at once (a deploy), the new server sometimes met the old one still closing the database and died with "database is locked", to be started again five seconds later. The launcher now leaves when the server and the agent have ended, and the database waits for a lock from its first statement.
- **A session is started again for a lost connection only when Claude Code has really given it up** ("not connected"), not for one call that was refused while the office restarted.

- **`pnpm check:changed` — a faster loop while developing.** It looks at what changed in the working tree (staged, unstaged and untracked; `--base <ref>` adds a whole branch), typechecks when a typechecked `.ts` changed, and runs the unit tests in the `test/` folder of each workspace a changed file belongs to, plus any changed `tests/e2e` file.
